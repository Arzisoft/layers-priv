# Transcript — Every week someone asks me about vendor lock-in.

> Every week someone asks me about vendor lock-in.

Every single week someone asks me about a vendor lock in. Should I multi cloud? Should I abstract everything? Should I build on my own? Here's what I actually tell clients and I'd never say this on Instagram because it requires a nuance.

Vendor lock in is a spectrum, not a binary. Using a managed database is a light lock in. Standard SQL, easy to migrate. Using a proprietary query language is heavy lock in. Rewrite required.

Using a platform's auth database storage and real time together is not a lock in, it is a marriage. And marriages work until they don't, right? The advice I give depends on the stage that one of my clients is in. Pre revenue, lock in, move fast, use everything in the platform. The risk of building too slowly is worse than the risk of switching it later, right?

But post revenue with traction, start decoupling. Not everything at once, just the pieces where the cost or the constraints becoming real. When you're fully scaled, you should already have abstraction layers. If you do not, it's not a project, it's a crisis. Lock in is only a problem if you've never planned to leave.

Plan the exit before you need it, but do not build the exit before you have traction for it.
