# Every week someone asks me about vendor lock-in.

Every week someone asks me about vendor lock-in.

Should I go multi-cloud. Should I abstract everything. Should I build my own.

Here is what I actually tell clients. And I would never say this on Instagram because it requires nuance.

Vendor lock-in is a spectrum. Not a binary.

Using a managed database is light lock-in. Standard SQL. Easy to migrate.

Using a proprietary query language is heavy lock-in. Rewrite required.

Using a platform's auth, database, storage, and real-time together is not lock-in. It is a marriage.

And marriages work until they do not.

The advice I give depends on the stage.

Pre-revenue: lock in. Move fast. Use everything the platform gives you. The risk of building too slowly is worse than the risk of switching later.

Post-revenue with traction: start decoupling. Not everything at once. Just the pieces where the cost or the constraint is becoming real.

Scaled: you should already have abstraction layers. If you do not, that is a project, not a crisis.

Lock-in is only a problem if you never planned to leave.

Plan the exit before you need it. But do not build the exit before you have traction.
