  ↳ **Matt Murphy** · 2026-07-27

  > Jafar, first off, don’t sell yourself short. You’ve already taken a web app a long way with zero traditional development experience, which means you’re doing the hard part: learning by building.
  > 
  > My biggest advice is not to chase every new tool yet, the basics are still powerful and more reliable, Claude Code is more than capable, but make sure you add structure.
  > 
  > Before each feature, define the expected behavior, data involved, permissions, edge cases, and what “done” means. Then have Claude build one controlled slice at a time instead of handing it the entire app. Thats where many early builders get caught up.
  > 
  > Keep your repo and documentation as the source of truth, commit frequently, and test every important flow before moving on. For critical work, have a second model or reviewer challenge Claude’s output rather than letting it grade its own homework. Cross checking is game changer.
  > 
  > The tools matter less than the process: plan → build a small slice → test it → review the evidence → fix the root cause → document the decision → move forward.
  > 
  > And honestly, the best way to make sure you’re not missing anything is to work through the Foundation tiers 1-13.
  > 
  > That’s exactly what they’re designed to do, show you the layers underneath the app that Claude may build without ever explaining. You’re in the right room. 👊😎

  ↳ **Matt Murphy** · 2026-08-08

  > Kevin, welcome to The Faction, bro. And yes, you’re right, a lot of the difference comes down to how you use the tools, not just which tool you pick.
  > 
  > The next game changer for you is probably getting out of the copy/paste loop entirely. Once the AI is working directly against your repo, reading the codebase, creating files, running tests, fixing its own mistakes, and working from a clear spec, the speed jump is massive.
  > 
  > From there, I’d focus on four things:
  > 
  > 1. Repo-native agents Codex, Claude Code, Cursor, etc. working directly in the project instead of you manually moving code around.
  > 2. Better context a solid README, architecture notes, coding rules, and a clear source of truth so the AI stops relearning the project every session.
  > 3. Smaller work orders don’t ask it to “build the feature.” Give it one bounded slice at a time, test it, commit it, then move forward.
  > 4. Automated verification let the AI run tests, linting, type checks, security scans, and eventually a second model review before you accept the work.
  > 
  > That’s the transition from “AI helping me code” to AI-directed engineering. The tool stops being a fancy answer box and starts becoming part of the development workflow.
  > 
  > Since you’re only a month in, don’t chase every shiny tool yet. Pick one repo-native builder, learn Git well enough to recover from mistakes, and work through the Foundations while applying each layer to the B2B app you’re already building. That’ll give you a much bigger return than collecting ten more subscriptions. 👊😎
