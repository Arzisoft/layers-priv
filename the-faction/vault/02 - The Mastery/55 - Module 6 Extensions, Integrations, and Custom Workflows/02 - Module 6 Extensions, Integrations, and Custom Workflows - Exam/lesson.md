# Module 6: Extensions, Integrations, and Custom Workflows — Exam

> Exam for **Module 6: Extensions, Integrations, and Custom Workflows** (The Mastery) — 25 questions, pass mark 80%. Correct answers are marked ✅ (read from each question's own post record; no quiz attempt was started to get them).

### Q1. A builder new to Cursor wonders whether they must wait years for an extension ecosystem to grow. What does this module say?

- **A.** Cursor is a VS Code fork, so most marketplace extensions install and work, giving builders a mature ecosystem on day one  ✅
- **B.** Cursor has no extension support by design, since AI capabilities replace what extensions provided in traditional editors
- **C.** Cursor's ecosystem is separate and young, so builders should expect a small catalog until developers port their extensions
- **D.** Extensions require a partner program application, so the catalog available to any given builder depends on approval status

> **Answer:** A

### Q2. This module says to choose extensions by a specific criterion. A builder is deciding between several. Which criterion applies?

- **A.** Install count, since popularity is the reliable proxy for quality and the most downloaded extension is the correct choice
- **B.** Typing power: pick extensions that speed up keystrokes, since faster manual editing is what separates builders at scale
- **C.** Reviewing power: pick extensions that make code more legible, since you direct the AI to build and review what it built  ✅
- **D.** Novelty, since recently published extensions track current practices better than established ones with legacy baggage

> **Answer:** C

### Q3. A builder asks what minimal extension set this module recommends starting with. Which set matches?

- **A.** A formatter, a linter for your language, and language support for your stack, adding more only when a task demands it  ✅
- **B.** A database GUI, a container manager, and a cloud console, since infrastructure visibility is the first gap to close
- **C.** A theme pack, an icon pack, and a startup dashboard, since a comfortable visual environment precedes any productive work
- **D.** An AI autocomplete, a snippet library, and a keystroke counter, since generation speed is the metric that compounds

> **Answer:** A

### Q4. This module calls Git 'a safety net' in a specific sense for AI-directed building. What is the connection?

- **A.** Git scans AI changes for malware, since version control's primary role in directed building is security screening
- **B.** Git prevents the AI from editing files directly, since all changes must pass through a commit approval gate first
- **C.** Git backs up to the cloud automatically, since the safety net is protection against hardware loss rather than bad edits
- **D.** Version control lets you accept the AI changes boldly because anything can be rolled back, making bold direction safe  ✅

> **Answer:** D

### Q5. A builder is about to direct a risky refactor of the data layer. What does this module say to direct first?

- **A.** Confirm everything is committed so the work can be rolled back, since commit-before-risk is the standing habit  ✅
- **B.** Disable Git temporarily, since version control hooks interfere with large refactors and re-enabling after is cleaner
- **C.** Export the project as a zip, since manual archives are more trustworthy than version control for major changes
- **D.** Delete old branches, since a clean branch list reduces confusion when the refactor inevitably needs untangling

> **Answer:** A

### Q6. A builder's commit history is all messages like 'updates' and 'fixes.' A regression appears. What does this module say they lost?

- **A.** Nothing, since Git bisect works on any history and message quality only matters for human readers writing changelogs
- **B.** The ability to reason over history: messages that describe changes let you and the AI find which change broke things  ✅
- **C.** Storage efficiency, since vague messages compress poorly and repository size is the real cost of careless committing
- **D.** Team permissions, since repositories with low-quality messages get flagged and lose collaboration features over time

> **Answer:** B

### Q7. A builder wants commit messages without writing them. Which directed pattern does this module model?

- **A.** Reusing one standard message forever, since consistency in the history matters more than describing each change
- **B.** Draft a commit message from the staged changes below: summary line under 60 characters, then two short bullets  ✅
- **C.** Skipping messages entirely, since empty commits are valid and messages are optional metadata for formal teams
- **D.** Generating messages weekly in batches, since retrospective summaries beat per-commit descriptions for accuracy

> **Answer:** B

### Q8. Something regressed and the builder suspects a recent change. Which history-first instruction does this module teach?

- **A.** Revert the last ten commits immediately, since bulk rollback is faster than investigation when a regression appears
- **B.** Diff the current code against the oldest commit, since comparing to the beginning shows everything that ever changed
- **C.** Rewrite the broken feature from scratch, since regressions signal code too fragile to be worth investigating at all
- **D.** Look at the recent commits and identify which change could have broken the specific feature that stopped working  ✅

> **Answer:** D

### Q9. A builder runs a delete-heavy command they found online without understanding it. This module has a rule for this moment. What is it?

- **A.** Run it in a hidden terminal, since commands executed outside the visible session cannot affect the tracked project files

- **C.** Run it twice quickly, since destructive commands prompt for confirmation and the second run is the real execution
- **D.** Only run it on Fridays, since end-of-week timing leaves the weekend for recovery if the command destroys something

### Q10. This module recommends a terminal arrangement for active projects. Which arrangement, and why?

- **A.** No terminal at all, since builders who direct AI should never see raw command output during a normal working session

> **Answer:** B

### Q11. A builder works across a database GUI here, a terminal there, and an editor elsewhere. What does this module say scatters?

- **A.** Context: the AI sees fragments instead of the whole workflow, which is why one-window workflows keep context in one place  ✅
- **B.** Their keybindings, since muscle memory cannot survive three applications and typing speed collapses across them
- **C.** Their billing, since each application meters AI usage separately and split workflows multiply their monthly plan costs
- **D.** Their extensions, since add-ons installed in one application quietly conflict with the others and silently disable themselves

> **Answer:** A

### Q12. When does this module say to automate a manual sequence into a task, script, or snippet?

- **A.** Immediately on day one, since anticipating friction and pre-building automation is what separates professionals
- **B.** Never, since automation is a distraction from building and manual repetition keeps the builder close to the work
- **C.** Only when a client requests it, since internal automation is unbillable effort that produces no visible deliverable
- **D.** After the same manual sequence has occurred three times, automating friction you have actually felt, not imagined  ✅
